# 箱子一鍵放入（Quick stack）

- 打開箱子時按 **Q**，或按箱子面板底部新增的「一鍵放入 (Q)」按鈕：背包裡「箱子已經有的同種物品」全部放進箱子。
- 同種 = 相同 dataId。品質、耐久不同也會放；房主能合併的就合併，其餘放到空格。箱子滿時放得下多少就放多少，剩下的留在背包。
- **快捷欄 1–0（背包第 0–9 格）不動**，手上的武器和工具不會被放進去。箱子沒有的物品也不動。
- 規則跟原版雙擊一致：任務物品不會放進地城戰利品箱（`isGeneric`）。商店、寵物背包，以及玩家背包（容器 id < 9）不提供此功能，按鈕會隱藏，按 Q 也沒有反應。
- 箱子改名輸入框或其他輸入框有游標時，按 Q 不會觸發。連按有 0.3 秒冷卻；就算重複送出，房主找不到已移走的物品也只會略過，不會複製或遺失。
- 按鈕位置：原生「整理」「全部拿取」原本在 x=±180，各寬 200，中間只剩 160px。現在三顆按鈕平分原本的外框寬度（約 173px、間距 20），依序是「整理｜一鍵放入｜全部拿取」；文字放不下時會自動縮小字體。非中文語系顯示 `Quick stack (Q)`。
- 純 client 端功能：只送出原版雙擊使用的 `ItemManager.MoveItemToContServerRpc`，**房主不用裝 mod**。房主有裝本整合包時，堆疊上限是 9999；沒有裝時照原版上限。
- 設定：BepInEx config `[QuickStack]`，`Enabled=true`、`Key=Q`。原生 22 個按鍵的預設值都沒有用到 Q。
- 目前不支援手把。

## Validation

`tests/run-quick-stack.ps1`：

- 規則單元測試，加上 3,000 輪隨機背包／箱子測試。以模擬房主執行 `MoveItemToContServerRpc`（找不到 id 就略過，先合併、再放空格、剩餘寫回原格），連按 1–3 次後檢查：各物品總數不變、快捷欄不變、其他種類和被擋下的任務物品不變、箱子不會多出新種類；上限分別測 99 和 9999。共 45,026 項。
- 故意改壞 10 種規則（拿掉快捷欄排除、快捷欄改成 9 格、拿掉任務物品檢查、拿掉同種過濾、空格算成物品、允許商店／寵物背包／玩家背包、未知物品照放），每一種都會被測試抓到。
- Cecil 檢查遊戲 API 與欄位、原版雙擊的 quest／pet 檢查、房主移動邏輯、容器 id 門檻 9、Q 沒有被原生按鍵佔用，以及整合包有啟動 `ChestQuickStack`。
- 從 `level2` 資產確認：`ButtonTakeAll`／`ButtonSort` 的 persistent listener 目標是右側 `extContainer` 的 `ContainerUI`，執行時靠這點找到按鈕。

遊戲內驗收：開箱按 Q 和點按鈕；快捷欄物品不動；箱子滿、部分放入；改名框打字不觸發；玩家背包、寵物背包不顯示按鈕；主機和客機各測一次；中英文介面的按鈕文字與排版。
