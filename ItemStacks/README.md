# 全物品 9999 堆疊（0.11.0 分支）

本功能整合在既有 `Tony.TeammateHealthBars.dll`，不依賴額外的堆疊 DLL。
原本不可堆疊的裝備、家具、食物、飲料、特殊物品及兩種牛馬，都可依相同物品狀態堆到 **9999**。
不同稀有度、耐久、充能、修理次數、metaInt 或武器屬性的物品分開存放，不覆蓋彼此資料。

## 實作方式

- 背包／箱子新增、拖曳合併、整理合併、拆分及數量 UI 使用獨立容量 9999。
- 保留 `ItemData.maxStack` 的原始數值。原生商店購買、掉落、物品建構、酒桶與工作站產出的數量，仍使用遊戲原始數值，不會生成 9999 件。
- 整合原 ItemStackerFix 的容量與原版商店／掉落保護，以及 StackableFood 的食物堆疊、單份上菜、批次上菜、服務員取餐與食物售價功能。
- 家具放置、學習配方、旗幟、轉換物品及工具損壞只消耗一件；配料的原生批次消耗保留。
- 耐久、充能、修理與武器狀態變更時，只修改一件，其餘副本保留原狀。背包無空位時，使用原生掉落流程保留剩餘副本；請留意腳邊物品。
- 充能總量包含所有副本；耗盡的容器依件數轉成空／髒容器，部分用量只改一件。
- 原生售價回傳型別為 UInt16。每次販售只賣掉總價不超過 65,535 的最大批次，其他物品留在原格；顯示的售價是該批次的價格，不是整疊總價。單件本身超過上限時不出售。

## 與原有兩個 DLL 共存

不修改、刪除或搬移 `ItemStackerFix.dll`、`KinkoCraft.StackableFood.dll`，也不改它們的 config。
SoftDependency 讓整合模組在它們初始化後執行：先取回舊模組保存的原始堆疊資料，再於記憶體中移除兩個舊 Harmony owner 的 patch，由整合版接管。
沒有安裝舊模組時，整合版也能獨立運作。預期相容版本為 ItemStack99Safe 1.0.9／StackableFood 1.0.10；無法取得舊模組原始資料時拒絕接管並記錄錯誤。
接管前核對遊戲 IL；安裝 patch 失敗會移除整合版 patch、還原先前數值並重新套用舊模組。血量面板、點唱機及馬匹仍繼續初始化。

- 基底：main 已提交的 `d3d286d`（0.10.0），包含牛馬長按 X 收回背包。只將該提交納入本分支，未修改 main。

## 驗證與限制

執行 `powershell -File tests/run-item-stacks.ps1`。需要現有 .NET 8 runtime 與遊戲的 Mono.Cecil.dll。
測試直接編譯正式 `ItemStacks/*.cs` 搭配測試替身，以 Mono.Cecil 讀取實際 Assembly-CSharp.dll 的 IL，核對 27 個 transpiler 目標、預期修改數量及 API 變更時拒絕套用的行為。
共 681 項檢查通過，另測數量守恆、滿背包／溢出、各 metadata、上菜／放置、充能、販售與接管失敗回復。
替身測試不會啟動真正的 Harmony detour、Unity、Netcode 或存檔系統，因此不等同遊戲內驗證。

待遊戲內驗證：所有玩家使用一致整合版；主機／客戶端各測 9998+2、9999+9999、拆分、跨箱搬移、丟棄撿回、不同品質裝備、工具損壞、飲料充能、上菜、家具／牛馬放置、商店分批販售、存檔重讀及晚加入同步。四位數 UI 是否擠出格子也需實際畫面確認。
若退回 99 上限版本，先將大堆疊拆回相容數量；舊版加入物品時可能直接截斷數量。
